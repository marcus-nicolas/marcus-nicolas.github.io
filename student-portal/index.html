01 / PRODUCT DESIGN · RESPONSIVE DASHBOARD

A clearer start
to the student day.

A concept redesign for a student portal dashboard, organized around three everyday questions: Where do I need to be next? What is due soon? Is there a notice I should know about?

01 / THE QUESTION

Make the first glance useful.

Starting hypothesis: student portals can place schedules, deadlines, and notices in separate areas. A student checking the dashboard between classes may have to scan several sections to work out what needs attention next.

This project narrows the dashboard to one job: help a student orient themselves and find the next important detail without exploring the full portal.

Scope note: This is a self-initiated concept. No students were interviewed, and no existing university portal or usage data was supplied. The problem is a design hypothesis, not a research finding.

02 / DESIGN INTENT

Keep the urgent visible. Keep the rest close.

  • Put the next class and nearest coursework deadline above routine updates.
  • Show time and location together so the class card answers “where and when?”
  • Give a notice a clear label and a separate visual treatment.
  • Keep the same priorities when the layout collapses to a phone.

The visual language uses warm neutrals and a restrained green, with a small orange signal for time-sensitive details. Color is paired with labels and position so it does not carry meaning by itself.

03 / LAYOUT DECISIONS

One overview, two useful reading paths.

On wide screens, the next-class card and deadlines sit side by side. The schedule and announcement follow below. On narrow screens, the dashboard becomes one column, with the next class first and deadlines directly after it.

The schedule toggle below lets a visitor compare a single-day view with the full week. The announcement can be dismissed from the current view. These interactions are illustrative and do not save data.

04 / WHAT I’D TEST NEXT

Check whether the hierarchy matches real student needs.

Next I would test the desktop and mobile concepts with students who use campus portals. I’d ask them to find their next class, locate the nearest deadline, and explain which notice they would act on. I would observe where they hesitate and revise the order, labels, and responsive behavior.

No usability findings or outcome metrics are claimed yet. The current prototype demonstrates a design direction for discussion, not a validated improvement.
