03 / WEB DESIGN · FRONT-END BUILD

A portfolio built
like a field guide.

The portfolio website is a project in its own right: an editorial visual system that connects the case studies, and a responsive front-end implementation built with semantic HTML, CSS, and JavaScript.

01 / THE DIRECTION

Give the learning journey a visual home.

Many early-career portfolios rely on the same centered hero, gradient background, and uniform project cards. I wanted this one to feel more personal to the work: curious, grounded, and connected to a campus setting without looking like a university website.

The “Fieldnotes” idea frames each project as an observation turned into an interface. A quiet map line, field labels, and paper-like surfaces give the site a recognizable visual thread, while the case study content stays direct and readable.

02 / VISUAL SYSTEM

Editorial type. Map-like details. Useful contrast.

  • Warm paper gives the canvas a softer character than stark white.
  • Deep green anchors navigation and primary actions; orange is reserved for small emphasis.
  • Serif headings provide an editorial voice, paired with a clear sans-serif for body copy and a mono face for labels.
  • Custom interface illustrations preview the project concepts without relying on stock imagery.

The system uses color in small, consistent roles and includes focus indicators and reduced-motion support.

03 / REFERENCE STUDY

Borrow the useful patterns. Keep the identity original.

The first reference made the owner’s name, role, work, and contact details easy to find. The second pairs project browsing with an interactive personal Q&A and appearance controls.

I carried those structural ideas into this site through a clear name and role in the hero, three focused project cards, direct contact links, the About Q&A, and the light/dark control. The visual direction—Fieldnotes, campus-map routes, and warm paper—was made for this portfolio.

I left out résumé, experience, testimonial, location, and activity-stat sections that would need details or evidence not supplied for this portfolio.

04 / FRONT-END NOTES

Build the layout around real reading order.

  • Semantic landmarks and a skip link help keyboard and assistive-technology users move through the page.
  • CSS Grid and flexible sizing adapt the hero, case-study list, and footer to smaller screens.
  • The mobile navigation exposes its open state with aria-expanded and closes on Escape or link selection.
  • A light/dark toggle updates the page’s CSS color tokens, and a native disclosure list gives the About section a short Q&A.
  • Project demos use native controls, labels, focus states, and client-side interactions.

The pages are static and require no build step. The personal details come from Marcus; the project scenarios and sample data are clearly labeled concepts.

05 / NEXT ITERATION

Keep the work personal and specific.

The portfolio now includes Marcus’s preferred name, contact email, and GitHub profile. As the projects develop, add only the feedback, decisions, and outcomes that reflect work actually completed.
